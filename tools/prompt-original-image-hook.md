# 任务：微信 Android 图片原图获取方案设计（hook 路径）

你是微信 Android 逆向专家。下面是一个正在运行的微信机器人项目遇到的真实技术问题，请基于给出的**已验证事实**（不要怀疑这些事实，它们是实测得出的）设计一套可落地的 hook 方案。项目环境是**混淆过的微信 8.0.70**，你在设计中必须给出「如何定位具体类/方法」的方法学，而不是只给假设的类名。

---

## 一、项目背景

- 项目名 FEAGLE：一个个人微信机器人。平板（三星 SM-X200，Android 13）上跑 Agent App，Agent 用 **LSPosed/Xposed 模块**（Xposed API 82）hook 微信进程，把收到的消息通过 WebSocket 上报到服务器（阿里云 ECS，国内），服务器再接大模型自动回复。
- 微信版本 **8.0.70**，**代码全混淆**（类名如 `pl.f2`、`y8`、`xv0.t9` 这种），但**字符串常量未加密**（dex 里明文存在）。
- Hook 环境：Xposed API 82（注意：`XposedHelpers.getField` 不存在，要用 `getObjectField`）；微信进程里可自由反射；**主进程 + :push 进程都会注入**，消息捕获（captureMessage）在主进程生效。
- 已能做静态分析：平板的微信 APK 已解包，`dexdump` 输出过 101 万行 dump（classes.dump.txt），可以搜类名/方法名/字段名。

## 二、已经跑通的链路（不要重新设计这些）

1. **消息捕获**：hook 微信消息入库入口（8.0.70 的 storage-helper 路径），拿到消息对象（类名 `y8`）→ 提取字段（`field_content`、`field_imgPath`、`field_lvbuffer`、talker、createTime、msgId、msgSvrId）。
2. **文本消息**：content 格式 = `发送者wxid:\n正文`，群名从 Contact 实体（`pl.f2`，rcontact 表映射类）的 `field_nickname` 拿，已缓存并随消息上报。
3. **图片消息（现状）**：`field_imgPath` 值形如 `THUMBNAIL_DIRPATH://th_<32hex>`，从中解析出 32 位 hash，然后在本地文件系统定位缩略图文件：`/data/data/com.tencent.mm/MicroMsg/<用户hash目录>/image2/<hash前2位>/<hash次2位>/th_<hash>`（注意：**文件名没有扩展名**，内容是已解密的 JPEG，497×340，约 6.8KB）。压缩成 base64 上报给服务器 → 大模型。**这就是当前在用链路，但只有缩略图。**

## 三、要解决的问题

**拿到图片的「原图」（更清晰版本），而不是缩略图。**

当前状况：微信默认**只下载缩略图**到本地（`image2/<前2>/<次2>/th_<hash>`），**原图不下载**——原图要等用户「点开图片查看」时才从 CDN 下载并解密存本地。已验证：开启微信「自动下载」设置对新图片无效（该设置只管视频/文件）。历史图片（没点开过的）也只有缩略图。

## 四、已验证的事实（实测证据，不要质疑）

1. **图片消息对象（y8）的 `field_content` 是一段 XML**，实测内容（脱敏后）：
```xml
<img aeskey="be3235a863a10f3089198a793bd443f3" encryver="1"
     cdnthumbaeskey="be3235a863a10f3089198a793bd443f3"
     cdnthumburl="305f020100044b304902010002046ca1d9a602032f578b020456b92b6f02046a71f5bc042462396666326366352d333533312d343832662d393963382d306135646565623535343561020405150a02020100040d004c4dff000000000000000000"
     cdnthumblength="6802" cdnthumbheight="340" cdnthumbwidth="497"
     cdnmidimgurl="（同上，与 cdnthumburl 相同的 hex）"
     length="38658" md5="2f82350750a6c41fb6f07e15a7b60e94"
     hevc_mid_size="22891" originsourcemd5="021c14f8403adb86be9ad0c65d82606b"/>
```
2. **`cdnthumburl`/`cdnmidimgurl` 是 hex 编码的二进制，解码后不是普通 URL**，而是一个 **ASN.1/DER 结构**（`30 5f 02 01 00 04 4b 30 49 02 01 00 02 04 6c a1 d9 a6 ...`），里面内嵌了一个 **IPv4 地址 `108.161.217.166`**（字节 `6c a1 d9 a6`）和一个 **UUID 字符串 `b9ff2fcf5-3531-482f-99c8-0a5deeb5545a`**。这是微信新版 CDN（mmtls）的定位信息，**不是 HTTP URL**。
3. **服务器直接 curl 该 IP 失败**（HTTP 000，连接不通）——微信 CDN 走 mmtls 私有协议，服务器侧无法直接下载。**所以「服务器下载 CDN」这条路径已死，不用考虑。**
4. `field_lvbuffer`（335 字节的 PB）里没有 http 明文（mmtls 的 DER 信息是二进制，扫描不到）。
5. 本地 `th_<hash>` 文件是**已解密的 JPEG**（微信下载时已解密），缩略图 497×340。
6. 原图大小 `length="38658"`（约 38KB，md5=2f823507...），即原图也就几十 KB，不是几 MB。
7. **dexdump 可用**：APK 的 dex 已 dump，可搜类名/字符串引用（字符串是明文，比如 `rcontact`、`@chatroom` 都能搜到）。

## 五、已排除的路径（不要重复建议）

- ❌ 服务器直接下载 CDN（mmtls 私有协议，IP 直连失败）
- ❌ 开启微信「自动下载」设置（实测无效，只影响视频/文件）
- ❌ 读数据库（EnMicroMsg.db 加密 + 项目铁律不读库）
- ❌ DexKit 运行时类搜索（此环境实测搜索全空，不可用）
- ❌ 让用户在 UI 上手动点开每张图（不可自动化）

## 六、可行的方向（请围绕这些设计，但可补充更好思路）

目标：**在微信进程内（Agent 的 Xposed hook 上下文），拿到图片的原图数据（解密后的 JPEG），或者触发微信把原图下载到本地再读取。**

可能的方向（任选或组合，给出你认为最优的）：
1. **hook 微信的图片下载/解码方法**：图片查看时微信会调用内部方法下载原图 + AES 解密（aeskey 已知，`encryver=1`）。如果能定位这个下载/解密入口（方法），就可以 hook 它或在消息到达时主动调用它，把原图写到本地（或直接拿到 byte[]）。
   - 定位思路请给出：从 dex 里搜什么字符串（比如 aeskey 相关的日志/常量、`ImageInfo`、`MMBitmapUtil`、CDN 下载相关的类名片段），或者从已知的消息处理链（`pl`/`y8` 消息对象 → 图片加载 UI）向上游找。
2. **hook 图片查看器（ChattingUI 的大图预览）**：用户点开图片时会走「大图预览 activity/组件」，它负责下载原图并显示。hook 它的「开始下载/加载原图」方法，在消息到达时**直接调用它**（传入消息对象），微信自己完成下载+解密+落盘，然后我们轮询本地新出现的原图文件。
3. **直接调用微信内部「按消息加载原图」的 API**：微信内部一定有「给定消息对象 → 下载并返回原图 Bitmap/文件」的方法（因为图片详情页就是这么干的）。定位它，调用它。
4. **解密路线**：如果本地其实已经有原图加密数据（比如 `.ref` 目录或 `image2/.ref/` 下的文件，实测该目录存在且有内容），结合 aeskey 也许能解密出原图。请评估这条路的可能性（微信是否把原图加密缓存留在本地）。
5. 其他你认为更优的思路。

**本地已知目录线索**：`image2/` 下除了 `th_<hash>` 文件，还有一个 `.ref/` 子目录（里面有 UUID 命名的文件，如 `d/e15aadc4-d81b-4baf-862b-5bd46d826cd3`），可能与 CDN 引用/缓存有关，可以结合分析。

## 七、约束与注意事项（必须遵守）

- **主进程**里执行（消息捕获在主进程），hook 安装要覆盖主进程；`:push` 进程的注入不要浪费。
- **不能 ANR/卡死**：下载原图可能耗时，hook 回调里只能发起，不能同步等待；读取/处理放后台线程。
- **诊断代码与正式实现分离**：先给「探测方案」（如何确认找到了正确的方法/类，用什么日志标记），探测通过后再谈正式实现。
- 反射要在混淆环境下可靠：**先反射实测再下结论**，不要假设某个类名一定存在。
- 给出每一步的**验证方法**（怎么确认 hook 生效、怎么确认拿到的是原图：比如对比文件大小 38658、md5 2f82350750a6c41fb6f07e15a7b60e94、或 JPEG magic bytes）。
- 如果方案需要新逆向（新类定位），请给出**具体的定位步骤**（搜什么字符串 → 怎么确认 → 怎么反射验证），而不是模糊地说「找到下载方法」。
