# 微信 8.0.70 逆向补充提问稿（群头像拼图 / bot 头像）

## 背景（上次咨询后的实测进展，请勿重复建议已排除的方案）

环境：微信 **8.0.70**（Android），LSPosed Xposed 模块 Hook，进程内反射，root 权限。
**铁律不变**：不读数据库（加密）、不走 CDN（外网被墙）、字段名实测不猜、新逻辑轻量可开关防 ANR。

上次咨询已完成的部分（无需再建议）：

1. **群名已解决**：Contact 实体类 = `pl.f2`（rcontact 表，字段 `field_username` / `field_nickname` / `field_conRemark` / `field_pyInitial` 等全部实测确认）。Hook `pl.f2` 的无参 String getter 方法（微信渲染会话列表时必然调用）→ 捕获实例 → 缓存 `talker → field_nickname` → 随群消息上报。已在真机验证（群名正确显示）。
2. **头像本地文件路径规律已验证**：`/data/data/com.tencent.mm/MicroMsg/<32位用户hash>/avatar/<md5前2位>/<md5次2位>/user_<md5>.png`（另有 `user_hd_<md5>.png` 高清版）。群 ID 和个人 wxid 同一套规律，实测命中（群 `58483015293@chatroom` 的 MD5 → 文件存在，7.4KB JPEG）。

4. 已定位 `com.tencent.mm.contact.s`（继承 pl.f2 的子类），其 `o3(String)->String` 方法静态调用原样返回参数（疑似 passthrough），非 getContact。

## Q1：群头像的「成员拼图」问题（重点）

现状：**用户的大多数群没有设置过群头像**，微信会话列表显示的是**群成员头像拼图**（宫格组合图）。这些群在 `avatar/` 目录里**没有群头像文件**（MD5 路径不存在）。

问题：

- **Q1.1** 微信的成员拼图是**客户端实时绘制**（每次渲染从成员头像合成），还是有**本地缓存文件**？有缓存的话路径和命名规律是什么？（我们只验证了 `avatar/` 目录，不确定拼图是否也在此目录或别的缓存目录，如 `sfs/`、`thumb/`。）
- **Q1.2** 如果拼图是实时绘制的、无缓存文件，我们打算 **Agent 侧自拼**：拿群成员 username 列表 → 逐个读成员头像文件（MD5 规律已通）→ 3x3 宫格合成 → 压缩上报。那么**群成员 username 列表从哪里拿最稳**？chatroom / GroupInfo / 群会话对象的哪个字段或方法？（需要类名候选或定位方法；注意我们已确认 Contact 实体是 pl.f2，但群成员列表应该在另一个对象里。）
- **Q1.3** 微信有没有「群未设置头像」的**默认头像资源**（比如内建默认图）？如果有，是否也在本地可读（路径/资源 ID）？
- **Q1.4** 群头像的变更感知：群主改了群头像后，本地 `avatar/` 文件何时更新？监听「群头像变更」的轻量入口是什么（会话列表刷新？某个事件/通知类？）——用于决定什么时候重新读取并上报。

## Q2：bot 自己的 wxid / UserInfo（bot 头像的前提）

现状：我们需要 bot 自己的 wxid（用于 MD5 拼 avatar 路径），以及自己的昵称/头像信息。

问题：

- **Q2.1** 8.0.70 上**自己 wxid 的最稳获取方式**是什么？候选：①Hook 自己发出的消息（sender 字段 = 自己 wxid）——但我们主要 hook 收消息路径，发消息路径没 hook；②UserInfo/profile 全局单例；③`userinfo` 表实体（同 rcontact 风格的 IAutoDBItem 类）。请给出**类名候选 + 定位方法**（上次 Contact 管理器候选类全失败的经历：`com.tencent.mm.model.r` / `model.aa` 等历史类名在 8.0.70 不存在，反射 dump 已确认）。
- **Q2.2** 自己的头像本地文件：wxid → MD5 → `avatar/` 路径，**是否与群头像同一套规律**？（我们推测是，但请确认有没有例外，比如自己的头像可能在别的目录。）
- **Q2.3** 自己头像变更（换头像）后本地文件何时更新？需要监听还是启动时读一次就够？

## Q3：传输与触发节奏（简单确认）

- 按上次建议我们采用「发现/变更时推一次 + Bridge 缓存」：群名已随消息上报。**头像的触发时机**：①群头像文件变化时；②Agent 启动时全量扫一遍有头像文件的群；③还是随群消息首次出现时懒加载？考虑到「一次只推一个、压缩 <50KB、128-256px JPEG q60-70」的约束，哪个节奏最省流量且不会漏更新？
